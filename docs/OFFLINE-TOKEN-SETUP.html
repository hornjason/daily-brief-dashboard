Offline Token Setup

Google OAuth setup for the Brief Encounters dashboard

For the AI Challenge, no local setup is needed

The team dashboard is live at demo.jasonhorn.io/dashboard — just open the link. No containers, no tokens, no OAuth configuration.

This guide is only needed if you want to run your own local instance.

Option 1: Use the Team Dashboard (Recommended)

No setup required

The shared team dashboard is already running with full Google OAuth configured. Open https://demo.jasonhorn.io/dashboard in your browser and start exploring. All data sources are connected — emails, calendar, Drive, Salesforce, everything.

Option 2: Setup Wizard (Local Install)

Web UI handles everything

If you want to run your own local instance:

  1. Start the dashboard: make up (or ask Jason to start it for you)
  2. Open your browser to: http://localhost:7777/dashboard/setup
  3. Click "Authorize Google Account"
  4. Sign in with your @redhat.com Google account
  5. Click "Allow" when Google asks for permissions (Gmail, Calendar, Drive)
  6. The wizard saves your token automatically — you're done
Verify it works: Refresh the dashboard — you should see email highlights, calendar events, and Drive files. If the page shows "No data", wait 30 seconds and refresh (first sync takes time).

Option 3: Manual Token Setup

For remote machines or headless setups

If the wizard doesn't work or you're setting up a remote machine:

  1. Get the token file — use the setup wizard on any machine with a browser: 
    podman run -d -p 7777:7777 --name daily-brief ghcr.io/hornjason/daily-brief-dashboard:latest
    Open http://localhost:7777/dashboard/setup, click "Authorize Google Account", and complete sign-in. The token saves to data/config/.google-token.json.
  2. Copy the token to the remote machine: 
    podman cp daily-brief:/data/config/.google-token.json ./
scp .google-token.json <remote-machine>:~/daily-brief/data/config/
  3. Restart the remote container: 
    make restart

Technical Notes

  • Token location in container: /data/config/.google-token.json (maps to host ./data/config/)
  • Scopes requested: Gmail read, Calendar read, Drive read/write (uploads account plans to Drive)
  • Token expiration: Refresh tokens are long-lived but may expire if unused for 6+ months
  • Security: Keep .google-token.json private — it grants full read access to your Google account
  • Rotation: To rotate, delete the token file and re-authorize via the wizard
