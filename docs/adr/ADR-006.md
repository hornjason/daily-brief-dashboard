# ADR-006: Test-only snapshot/restore endpoints for parallel Playwright execution

**Date:** 2026-03-30
**Status:** Accepted

## Context

DailyBriefDashboard tests mutate shared config files (`data/config/aes.json`, `data/config/customers.json`) that are also the application's persistence layer (see ARCHITECTURE.md — "Config files mutated at runtime is intentional"). Running Playwright tests in parallel without isolation causes state bleed between tests: a test that clears AEs poisons any concurrent test that expects AEs to exist.

The previous approach — `workers: 1` in playwright.config.ts — serialized all tests. This made the 200+ test suite take 5+ minutes and prevented any parallelism benefits.

## Decision

Add two test-only HTTP endpoints to `server.ts`, gated behind `NODE_ENV !== 'production'`:

- `POST /api/__test/snapshot` — reads `aes.json` and `customers.json` and returns them as a JSON snapshot
- `POST /api/__test/restore` — accepts a snapshot JSON body and atomically writes it back to `aes.json` and `customers.json` using a write-then-rename pattern

These endpoints are consumed by the `serverState` fixture in `test/fixtures.ts`, which auto-snapshots before each test and restores after — transparently, with no per-test boilerplate.

With this isolation in place, `workers: 1` and `fullyParallel: false` are removed from `playwright.config.ts`.

## Consequences

**Positive:**
- All tests can run in parallel — no sequential bottleneck
- No per-test `beforeEach`/`afterEach` required for state isolation
- Fixture is `auto: true` — applies to every test without opt-in

**Negative:**
- Server.ts has test-only code paths. This is unavoidable given that the config files are the persistence layer — there is no other isolation point.
- If `NODE_ENV` is accidentally set incorrectly in production, the endpoints would be exposed. Mitigation: the `gated behind NODE_ENV !== 'production'` check is explicit and documented.

**Non-issues:**
- The endpoints cannot cause data loss in production — they are behind an env var check
- Atomic write (write to `.tmp` then rename) prevents partial-write corruption even if the process is killed mid-test
