The Walkthrough — 7 Steps

1

Open the Dashboard

Navigate to demo.jasonhorn.io/dashboard or your local instance at localhost:7779. You'll see the portfolio overview — all demo accounts as cards in a grid with health scores, pipeline, and subscription data.

2

View the Baseline Brief

Click a customer account card. Scroll through the Customer Brief. This is the "before" state — note:

  • Which support cases are highlighted
  • What themes appear in the brief narrative
  • The recommended actions and their "why now" reasoning
  • How many cross-reference connections appear in the intelligence graph
3

Refresh Data Sources

Use the Data Freshness panel to refresh any source. Click Refresh on Cases, Pipeline, Subscriptions, or any other source. The platform re-pulls live data — new cases, updated opportunities, changed subscriptions flow in automatically.

No file editing required. Everything happens through the UI.

4

Add a Document to Google Drive

This is the most powerful input method. Drop any document into the customer's shared Drive folder — a competitive alert, meeting notes, a partner update, an expansion opportunity.

What happens: On the next regeneration, Gemini reads the document and synthesizes its content into every consumer output automatically. A competitive alert about Kubernetes migration becomes a new initiative in the account plan, a talking point in meeting prep, and updated context in the brief.

Verified: adding a VMware migration alert produced a new "VMware to OpenShift Consolidation" initiative. Removing it and regenerating removed the initiative. The system reads fresh every time.

Anyone on the team can do this. No code, no config — just drag a file into Google Drive.

5

Regenerate an Output

After adding a Drive document, Jason will regenerate the output during the live demo. On the shared instance, regeneration is coordinated — Jason runs it, everyone sees the result.

The consumers that update:

  • Customer Brief — refresh icon on the Brief section
  • Account Plan — Generate on the Account Plan tab (quality-scored, uploaded to Drive)
  • Value Positioning — Generate button builds competitive positioning
  • Intelligence Docs — Company Intel + Industry Analysis (also appear in Drive)

The pipeline re-runs with the updated data. The new Drive document is synthesized into every output automatically.

6

Compare Before and After

Compare the updated outputs with what you saw in Step 2:

  • New data highlighted — refreshed cases, Drive docs, or pipeline changes appear in the brief
  • Cross-references — the intelligence graph shows new connections between signals
  • Ripple effect — the same input change affects Brief, Account Plan, Meeting Prep, Campaigns, and more simultaneously

See the Challenge Workflow visual for the full before/after comparison framework.

7

Explore Further

  • Intelligence Graph — click the graph visualization to see how signals connect across sources
  • Other Accounts — different signal patterns produce different briefs
  • Product View — signals grouped by Red Hat product line
  • Account Plan — 9 hidden inputs, 11 quality checks, auto-uploaded to Drive

Themes × Judging Criteria

Every idea fits one of three themes. Each theme is designed to score across the four judging criteria (25% each).

Judging Criterion (25% each) A: Show Your Work B: Make It Smarter C: Make It Shine
Innovation ● Primary ● Primary ○
Feasibility ● Built on existing data ● Small/medium features ● Primary
User Experience ● Primary ● "Why now" reasoning ● Primary
Technical Excellence ● Primary ● Primary ● Clean implementation

A: "Show Your Work"

Make the hidden visible. The account plan has 9 inputs and 11 quality checks — the user sees none of it. Surface provenance, data maturity, quality scores.

Judges see: Innovation (nobody else exposes this), Technical Excellence (real provenance, not mocked), UX (users understand what went in), Feasibility (data already exists — just surface it)

#27 #28 — Provenance, data maturity

B: "Make It Smarter"

Add the "why." Recommendations say WHAT — this theme adds the signal chain that explains WHY. Delta tracking, trend indicators, visual connections.

Judges see: Innovation (AI explains its reasoning), Technical Excellence (signal chains across 9 sources), UX ("why now" makes actions understandable), Feasibility (small/medium features on existing engine)

#29 #30 — Signal chains, delta tracking

C: "Make It Shine"

First impressions win. Confusing labels, dead tabs, inconsistent layouts — your fresh eyes catch what the builder can't see.

Judges see: UX (polished, professional interface), Feasibility (quick wins that ship fast), Technical Excellence (clean implementation), Innovation (loading states, progress animations)

#31 #32 — UX polish, clarity

Every theme touches all four criteria. The matrix shows where each theme scores strongest — together they cover the full rubric.

What to Look For

When exploring the platform, evaluate through the judging criteria lens:

  • ▸ Signal Coverage — Does the brief capture all relevant signals? What's missing?
  • ▸ Cross-References — Are connections between signals meaningful and actionable?
  • ▸ Brief Quality — Would this help you prepare for a real customer meeting?
  • ▸ Hidden Context — What would you want to know about HOW the output was generated? (Theme A)
  • ▸ Missing "Why" — Where do you see a recommendation without the reasoning chain? (Theme B)
  • ▸ Confusing Labels — Anything unclear, jargon-heavy, or hard to understand? (Theme C)

What makes a great submission

1. What was surprising or unexpected in the output
2. What information was missing that you'd need for a real customer conversation
3. Which cross-references were useful and which felt like noise
4. Ideas for new features, layouts, or signal sources
5. Anything that confused you — every confusion is a Theme C improvement
6. Try the Drive workflow — drop a document, regenerate, and describe what changed

The Drive Contribution

The easiest way to contribute is through Google Drive. Drop a document (competitive alert, meeting notes, market analysis, partner update) into the customer's shared folder, then regenerate the brief or account plan. Describe what changed — that observation IS your submission. You don't need to write code to prove the platform works.

Not a GitHub person?

Post ideas in Slack using this format — Jason will convert them into GitHub issues:

IDEA: [Short title]
THEME: A / B / C
WHAT: [2–3 sentences — what should it do?]
WHY: [1 sentence — why it matters for customer conversations]
IMPACT: Must-have / Strong addition / Nice-to-have
