The Opportunity — What Theme A Changes

Today: User presses a button → output appears. Zero visibility into what went in.

After Theme A: Every consumer output shows a provenance panel: which inputs loaded, how many tokens each contributed, what's missing, and how to improve it. The ProvenanceEntry[] array already exists in the code — it tracks { source, loaded, tokenEstimate } for every input. We just need to surface it in the UI.

The meeting prep consumer uses the most inputs (10/12) — it's the richest provenance story. The customer brief uses its own dedicated pipeline (★) with 9 direct inputs — bypassing buildConsumerContext entirely. The account plan uses 7/12 shared inputs plus the quality scorecard and Drive upload — it's the hero demo.
