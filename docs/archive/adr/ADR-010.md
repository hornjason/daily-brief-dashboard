# ADR-010: Account Intelligence Pipeline — Dual-Write Cache Pattern

**Date:** 2026-04-04
**Status:** Accepted
**Decided by:** Jason Horn

---

## Context

The account intelligence pipeline (`src/account-intelligence.ts`) runs a multi-step AI analysis for each customer and writes the output to Google Drive as a document. This Drive document serves as the human-readable, persistent record of customer intelligence.

The brief generation pipeline (`src/customer.ts` → `buildXmlSources()`) assembles XML from all available data sources before calling Gemini. Intelligence documents in Drive were never included in brief generation — the pipeline had no mechanism to read them back.

Two options were considered:

**Option A — Drive read-back:** Have `buildXmlSources()` call the Drive API to fetch the intelligence document before each brief generation. Problem: Drive API latency adds 500-2000ms to every brief request. Quota concerns on heavy use. Complex error handling for Drive auth failures during brief generation.

**Option B — Local JSON cache (dual-write):** The intelligence pipeline writes a second copy to `data/cache/intelligence/{slug}.json` at the same time it writes to Drive. The brief pipeline reads the local file — fast, no API call, no quota.

---

## Decision

**Option B — Dual-write.** The intelligence pipeline writes to both destinations on every run:

```
Account Intelligence Pipeline
  → POST /api/intelligence/:customer/generate
      ├── Step 1: Gather signals (parallel where possible)
      ├── Steps 2+3: Run in parallel (Promise.allSettled)
      │
      ├── Write → Google Drive (source of truth, human-readable)
      └── Write → data/cache/intelligence/{slug}.json (local read cache)

Brief Generation Pipeline
  → buildXmlSources()
      └── Read → data/cache/intelligence/{slug}.json
          └── Include as <source type="account_intelligence"> in brief XML
```

Google Drive remains the authoritative store. The local JSON is a read-through cache — it is never used as input for Drive writes, and it does not need to be synced from Drive.

---

## Consequences

- Brief generation gains access to intelligence content with zero API latency
- Drive quota is not affected by brief generation frequency
- If the intelligence pipeline has never run for a customer, the local JSON doesn't exist — `buildXmlSources()` skips the source gracefully (no error)
- If the container is rebuilt or the `data/cache/intelligence/` directory is deleted, intelligence content is absent from briefs until the intelligence pipeline runs again — Drive is unaffected
- The `data/cache/intelligence/` directory must be inside the bind-mounted `data/` volume to survive container restarts
- Job state persisted to `data/cache/intelligence-jobs.json` via `setJob()` wrapper in `account-intelligence.ts`; initialized via `initJobPersistence(cacheDir)` called from `server.ts` on startup

## Amendment — Drive Discovery Fallback (2026-04-19, BKL-AI-INTEL-02)

After a cache wipe, the local JSON is absent even when Drive docs exist. To prevent unnecessary regeneration (which overwrites Drive docs and burns Gemini tokens), `GET /api/customer/:name/intelligence-status` gained a three-tier resolution:

```
1. Memory (in-process jobs Map)         — fastest, covers active runs
2. Disk cache (intelligence/{slug}.json) — covers docs written in a prior server lifetime
3. Drive scan (Account Intelligence subfolder) — covers cache-wiped state
```

Drive scan: reads `{customer.name} - Company Intelligence` and `{customer.name} - Industry Analysis` from the customer's Drive folder. Read-only — never creates folders or docs. On hit, writes URLs + `discoveredAt` timestamp to disk cache and returns `status:'complete'`.

**Staleness:** `discoveredAt` field in cache JSON. If absent or >7 days old, Drive is re-scanned on next status poll (2 lightweight `files.list` calls — no Gemini).

**Auto-generate on Drive miss:** If Drive scan finds no docs and no job is active, `runIntelligencePipeline` fires automatically (non-blocking) and the endpoint immediately returns `status:'running'`. This ensures the panel is never stuck in a "Generate" prompt for a customer who should already have docs but lost them.

**Force:** `POST /api/customer/:name/generate-intelligence?force=true` explicitly regenerates via Gemini regardless of cache state. The UI "Generate" button remains for intentional refreshes only.
