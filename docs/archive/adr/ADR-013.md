## ADR-013 — Data Ingestion Tier Standard

**Status:** Accepted  
**Date:** 2026-04-17  
**Author:** Serena Blackwood (architecture review), Jason Horn (decision)

---

### Context

DailyBriefDashboard ingests data from 22 distinct sources. Each source had a bespoke caching implementation — some using wall-clock TTL, some SHA256 content hashing, some Drive modifiedTime probes, and many with no cache at all. This inconsistency caused unnecessary Gemini API calls, redundant Drive API reads, and unpredictable brief generation costs.

Serena Blackwood's architecture review (2026-04-17) identified 8 classes of inconsistency and found that per-customer-product-intel (`customer-product-intel.ts`) was the only data path with a correct content-addressed cache. All other paths needed to be brought up to that standard.

---

### Decision

All data ingestion paths are classified into one of four tiers. Tier assignment determines invalidation strategy, TTL, and write-side behavior. Every new data type must be assigned a tier at creation time.

---

### Tier Definitions

#### Tier 1 — Live (no cache)
**Trigger:** Every call.  
**Examples:** OAuth tokens, scraper mutex state, "is bootstrap running" flags.  
**Write-side:** In-memory only. No disk persistence.  
**TTL:** None — ephemeral by design.

#### Tier 2 — Time-boxed
**Trigger:** Wall-clock TTL expiry.  
**Examples:** Gmail emails, Google Calendar meetings, live RH subscription API.  
**TTL range:** 15 min – 6 h. Default: 2 h.  
**Write-side:** Unconditional overwrite on cache miss. No hash guard — data drift is expected and acceptable.  
**Cache key:** `{customerSlug}-{dataType}.json`  
**Cache shape:** `{ data, cachedAt, ttlMs }`

#### Tier 3 — Content-addressed
**Trigger:** Source fingerprint mismatch (not time).  
**Examples:** Drive docs (fileId + modifiedTime), doc classifications (content SHA256), SF bookings sheet data (row SHA256), brief synthesis (input XML SHA256 — future).  
**Write-side:** Hash-guarded — if existing fingerprint equals new fingerprint, skip write and preserve `cachedAt` to prevent downstream cascade invalidation.  
**Cache key:** `{customerSlug}-{dataType}-{fingerprint}.json` OR standard path with `fingerprint` field inside.  
**Cache shape:** `{ data, fingerprint, cachedAt }`  
**TTL:** None by default. Optional 7-30d safety-net TTL for data types where the fingerprint source can drift without a clear event (e.g. world knowledge changes underlying intelligence docs).

#### Tier 4 — Long-lived / Manual
**Trigger:** TTL safety net (7–30 days) + explicit `force` flag.  
**Examples:** Account intelligence (company + industry briefs), product summaries, domain inference.  
**Write-side:** Idempotency guard — don't overwrite identical output. Preserve `generatedBy` and `reason` metadata.  
**Cache shape:** `{ data, cachedAt, generatedBy?, reason? }`  
**Refresh trigger:** TTL expiry OR `?force=true` OR upstream dependency change (e.g. industry classification reset cascades to industry analysis invalidation).

---

### Standard Read/Write Contract

Every cache path must implement this shape, regardless of tier:

```typescript
read(key: string): { data: T; cachedAt: string; fingerprint?: string; ttlMs?: number } | null
write(key: string, data: T, opts?: { fingerprint?: string; ttlMs?: number }): void
invalidate(key: string): void
```

Tier enforcement (TTL check, fingerprint comparison) lives in `cache-layer.ts`. Consumers do not implement their own staleness logic.

### Consequences

- Drive doc cache (Tier 3) eliminates the largest single per-brief cost: Drive export + PDF Gemini multimodal re-runs on every brief.
- Doc classification cache (Tier 3) eliminates N Gemini calls per brief for stable customer Drive folders.
- Brief input fingerprint (Tier 3, BKL-AI-FP-03) makes quiet customers free to serve after initial generation. Shipped 2026-04-19.
- Corpus delta snapshot (Tier 3, BKL-AI-FP-09) reduces Gemini input tokens by ~80–90% for customers with large Drive folders where only one doc changes. Shipped 2026-04-19 (commit 73a753b).
- `cache-layer.ts` becomes the single owner of tier semantics. New data paths import from there — no bespoke staleness logic in consumers.
